# Clean UI

A modular skill. This file is only the router: it tells Claude where everything lives and how the parts connect. The detail is in the folders.

The look it produces: a full-bleed photo or flat base, one accent color, a heavy headline that says exactly what the thing is, one supporting sentence, two buttons. Nothing else competes with it. AI-generated UI hedges with gradients, badges, subheadings, and decorative symbols; this skill fixes that with subtraction and specificity.

## Layout

```
clean-ui/
├── SKILL.md              this router
├── manifest.json         every command, what it reads, calls, writes (source of truth)
├── INSTALL.md, docs/     installation, audit coverage, configuration, guidance (for people, not read per command)
├── examples/, tests/     sample pages and the test suite
├── core/                 shared by all commands
│   ├── rules.md          design rules: color, type, symbols, information, copy, spacing
│   ├── workflow.md       how a page is built
│   ├── delivery.md       how work is handed back
│   ├── hooks.md          snapshot before, audit and state after
│   ├── state.md          session scheme shared across commands
│   ├── preview.md        --preview (dry run) rules shared by file-changing commands
│   ├── graph.md          generated map of how commands connect
│   ├── tokens/           rules.json (all thresholds) and base.css (token names)
│   └── scripts/          audit, palette, snapshot, state, extract_palette, analyze_layout, build, validate
└── commands/<name>/      one folder per command
    ├── COMMAND.md        the command's own instructions and wiring
    ├── references/       background and checklists for this command
    └── tokens/           data and code snippets for this command
```

## How to handle a message

1. **Starts with a command?** Open its folder, read `COMMAND.md`, then read the files in its wiring table ("Reads"). Follow the steps. Run the pre-hooks and post-hooks in `core/hooks.md` if the wiring says the command modifies files.
2. **No command, but `/flawless` is on** (state `active` is true): treat any UI request as the matching command. A new page is `/new`. A change to an existing page is `/edit`. A pasted screenshot is `/ref`.
3. **No command and `/flawless` is off, but a UI task triggered this skill:** build with `core/workflow.md` and `core/rules.md`, then run the post-hooks.
4. **Unknown command:** say so and show `/flawless-c`.
5. **Ambiguous target:** if two pages could match, ask which in one question. Never guess.

## Rules that apply everywhere

- **Preview on request.** `--preview` on a command that supports it shows the change and the resulting audit without writing anything (`core/preview.md`). `/audit --explain` explains each finding.
- **Project settings.** If a `flawless.config.json` exists next to the page, the audit applies its mode, brand colors, and accessibility target (`docs/configuration.md`). Tell the user when a mode relaxed a rule.
- **Say what the audit cannot see.** A clean script audit is not a full review. See `docs/audit-coverage.md`.
- **Scheme stays.** No command changes colors, fonts, radius, or spacing as a side effect. Only `/palette`, `/match`, the colors and fonts category of `/edit`, and `/flawless` setup write the scheme.
- **Rules are defaults, not vetoes.** If a request breaks one, ask keep-or-override once, then follow the answer and remember it for the conversation.
- **Never invent facts.** No made-up statistics, reviews, prices, hours, or addresses.
- **One question round.** Commands that need choices use one round of `ask_user_input_v0`, at most three questions.
- **Palette and photo must agree.** One is fixed and the other adapts, and the user decides which (`/match`). A palette the user stated stays; the photo is graded or swapped.
- **Audit before delivering.** Every file Claude changes is audited and its errors fixed first.

## Maintaining the skill

Edit `manifest.json` when a command's inputs, calls, or hooks change, then run `python core/scripts/build.py` (regenerates wiring, the command table, palettes, and the graph) and `python core/scripts/validate.py` (checks files, links, cycles, hooks, and that generated content is current). Thresholds live only in `core/tokens/rules.json`.
