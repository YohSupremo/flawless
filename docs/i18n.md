# Internationalization

The shipped rules and banned word list are written for English copy. The layout and accessibility rules apply to any language. When the page is not English, adapt these:

## Language and direction

- Set `lang` on `<html>` to the real language (`lang="fil"`, `lang="de"`). The audit only checks that `lang` exists, not that it is right
- Right-to-left languages: set `dir="rtl"` on `<html>`. Use logical CSS properties (`margin-inline-start`, `padding-inline`, `inset-inline-end`, `text-align: start`) instead of left and right, so one stylesheet serves both directions. Mirror directional icons; do not mirror logos or numerals
- Mixed-direction text: wrap the foreign run in `<bdi>` or `<span dir="ltr">`

## Text length

- Plan for 30 to 40 percent longer text in many languages than in English. Buttons and headlines must wrap or grow, not clip. Do not set fixed widths on buttons or labels
- The 8-word headline limit is an English guide. Chinese, Japanese, and Korean read much shorter per idea; German compounds are long. Set `max_headline_words` in `flawless.config.json` to suit the language, and judge by lines (two at most), not only by words
- Test the longest translation, not the English

## Typography

- Choose fonts with the needed scripts. The Latin-only display font in the defaults will fall back for other scripts; set a real fallback stack for each script
- Do not use all-caps for scripts without case, and avoid letter-spacing on cursive scripts such as Arabic

## Numbers, dates, currency

- Format with the locale (`Intl.NumberFormat`, `Intl.DateTimeFormat`), not by hand
- Never hard-code `1,000.00` or `MM/DD/YYYY`

## Copy rules

The banned phrases, the slash and em dash rules, and the "plain words" rule need native review. A word list from English will not catch filler in another language. Have the agent apply the principles, then a native reader check the copy.
